Lezione 1 · ~15 minuti

Dal sorgente all'eseguibile

Crei, compili e lanci il tuo primo progetto Rust, e impari a leggere un errore del compilatore.

Perché ti serve (missione)

Il backend del tuo progetto open source sarà, prima di tutto, un progetto Cargo. Tutto quello che farai da qui in avanti (server HTTP, database, test) passa dai tre comandi di questa lezione.

1. Un po' di teoria: chi esegue il tuo codice?

Un processore capisce solo codice macchina. Il testo che scrivi (il sorgente) deve essere tradotto. Ricordi i linguaggi che conosci? Lo fanno in tre modi diversi:

LinguaggioTraduzioneCosa ottieniChi libera la memoria
Cgcc compila tutto primaeseguibile nativotu, con free()
Java / Apexjavac → bytecode, poi la JVMbytecode per una macchina virtualeil garbage collector
Pythonl'interprete legge mentre esegueniente da distribuire, serve l'interpreteil garbage collector
Rustrustc compila tutto primaeseguibile nativoil compilatore decide quando (ownership)

Rust è quindi un linguaggio compilato in anticipo (ahead-of-time) come il C: compili una volta e puoi dare l'eseguibile a chi non ha Rust installato.[1] Però, a differenza del C, ti garantisce la sicurezza della memoria senza un garbage collector, grazie al sistema di ownership, che vedremo presto.[2]

Rust è anche a tipizzazione statica, come C e Java: il compilatore deve conoscere il tipo di ogni variabile al momento della compilazione (spesso lo deduce da solo).[3] Così molti errori li scopri compilando, non in produzione.

2. Gli attrezzi

  • rustup installa e aggiorna Rust.
  • rustc è il compilatore. Lo userai quasi mai direttamente.
  • cargo è lo strumento di build e il gestore di pacchetti (pensa a Maven o Gradle per Java). Crea i progetti, scarica le dipendenze (i crate), compila, esegue e lancia i test.[4]

3. Fallo tu

Esercizio · la tua vittoria di oggi
  1. Installa Rust seguendo rustup.rs (su Windows scarica l'installer), poi verifica con cargo --version.
    Non sei al tuo computer? Fai i passi 4 e 5 con i pulsanti ▶ Apri nel Playground: il codice si apre già pronto nel browser, premi Run. Torna ai passi 2-3 quando puoi.
  2. Dalla cartella del repo crea un progetto: 
    cargo new pratica/ciao
cd pratica/ciao
  3. Guarda cosa ha creato Cargo e lancia il programma: 
    ciao/
├── Cargo.toml      # manifesto: nome, versione, dipendenze
└── src/
    └── main.rs     # il codice
    cargo run
   Compiling ciao v0.1.0 (…/pratica/ciao)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.36s
     Running `target/debug/ciao`
Hello, world!
    cargo run ha compilato e poi eseguito l'eseguibile che trovi in target/debug/.
  4. Apri src/main.rs: 
    fn main() {
    println!("Hello, world!");
}
    Al posto di "Hello, world!" fai stampare un messaggio tuo e rilancia cargo run.
  5. Rompilo apposta. Sostituisci il corpo di main con questo: 
    fn main() {
    let x = 5;
    x = 6;
    println!("{x}");
}
    Lancia cargo run e leggi l'errore: 
    error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:3:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++
    Applica il suggerimento (let mut x) e rilancia: ora stampa 6.

Cosa è appena successo

In Rust le variabili sono immutabili per impostazione predefinita. Per poterle modificare devi dirlo esplicitamente con mut.[5] In C e Java è il contrario: tutto è modificabile a meno che non scrivi const o final.

E guarda com'è fatto l'errore: ti dice dove (file, riga, colonna), perché (la prima assegnazione è alla riga 2) e come rimediare (il help: con i +++). Gli errori di Rust sono pensati per insegnarti. Leggerli fino in fondo è la competenza più utile di tutto il percorso.

Ultima cosa: println! ha un ! perché è una macro, non una funzione. Per ora ti basta sapere che {x} dentro la stringa stampa il valore di x.

4. Richiamo

Prova a rispondere senza tornare su. Lo sforzo di ricordare è proprio ciò che fissa le cose.

1. Cosa produce cargo build su un progetto Rust?

Rust compila in anticipo in codice macchina, come il C. Lo trovi in target/debug/.

2. Qual è la differenza principale con Java nella gestione della memoria?

Niente GC e niente free() manuale: è il sistema di ownership a stabilire, in compilazione, quando liberare la memoria.

3. A cosa serve cargo check? (Indizio: è nella fonte primaria qui sotto.)

Verifica che il codice compili senza generare l'eseguibile, quindi è più veloce di cargo build. Ottimo da lanciare spesso mentre scrivi.

4. Cosa succede compilando let x = 5; x = 6;?

Errore di compilazione E0384. Si risolve con let mut x = 5;.

5. Se hai più tempo

  • Lancia cargo build --release e confronta target/release/ con target/debug/. Quale dei due useresti in produzione per il backend, e perché?
  • Installa Rustlings (cargo install rustlings, poi rustlings init) e fai gli esercizi intro e variables. Ideali anche per le sessioni da 10 minuti.
Fonte primaria da leggere

The Rust Programming Language, capitolo 1: Getting Started, il libro ufficiale (gratuito). Se preferisci una versione con quiz integrati, c'è l'edizione interattiva della Brown University.

Hai dubbi?

Chiedi al tuo docente (Claude) qualsiasi cosa non sia chiara: un errore che non capisci, l'installazione che non va, un concetto di teoria da ripassare. Quando hai finito, dimmi com'è andata: incollami l'output o raccontami cosa hai sbagliato nel quiz, così la prossima lezione parte da lì.
